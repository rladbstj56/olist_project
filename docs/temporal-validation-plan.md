# Olist 시간 분할 검증 설계

작성일: 2026-10-03. 현재 상태: **승인된 Track B 1회 학습·시간 평가 완료**. 아래 설계 본문은 실행 전 합의 기록을 보존합니다. 실행 결과와 한계는 [결정 로그30절](modeling_decision_log.md#30-시간-분할-track-b-1회-학습과-상품-수별-진단--2026-10-03)을 확인합니다.

## 목적과 이번에 답할 질문

“과거 주문으로 학습한 Track B가 이후 주문의 낮은 만족도를 얼마나 찾아내는가”를 점검합니다. 기존 무작위 분할 결과를 대체하는 것이 아니라, 다른 평가 조건의 결과를 별도 보관합니다. 시간 순서로 나누어도 당시 피처 값·모든 고객 모집단을 완벽하게 복원한 것은 아닙니다.

첫 실험은 Track B만 대상으로 제안합니다. 주문 시점 사전 예측이라는 사용 목적과 직접 연결되기 때문입니다. Track A는 배송 후 진단이고 Track C는 배송일 분위수 모델이므로 같은 실행에 섞지 않습니다. 기존22개 피처·LightGBM 설정·라벨 정책을 유지해 변경 원인을 줄입니다. 이번 문서 작성 중에는 어떤 모델도 학습하지 않았습니다.

## 쉽게 보는 검증 절차

1. 2018년1월1일 직전에 실제로 결과를 알 수 있었던 과거 주문만 모읍니다.
2. 그 자료로 모델과 결측 대체 기준을 한 번 학습합니다.
3. 2018년1–3월 주문으로 위험 기준점을 선택하되,4월1일 전에 정답을 확보한 주문만 선택에 사용합니다.
4. 모델과 기준을 고정해4–7월 주문을 예측하고, 이후 기록된 정답으로 성능을 계산합니다.

첫 실험에서는 검증 자료까지 합쳐 다시 학습하지 않습니다. 학습을 한 번으로 고정하면 어떤 모델을 평가하는지 명확하고, 비교 도중 학습 범위가 바뀌는 일을 막을 수 있습니다. 더 최신 자료로 갱신하는 모델은 이후 별도 실험입니다.

## 기간과 표본 제안

아래 경계는 자정 기준이며 시작일은 포함, 종료일은 제외합니다. 원본 시각은 시간대 정보가 없는 값으로 읽었고 임의로 UTC나 한국 시간으로 변환하지 않습니다. 달력 분기와 완결된 월을 기준으로 선택했으며 시간 모델의 성능을 보고 고른 경계는 아닙니다. 8월은 데이터의 마지막 부분 월이므로 첫 평가에서 제외합니다. 과거 무작위 분할에서 이미 사용한 데이터이므로 ‘처음 보는 최종 홀드아웃’이라고 부르지는 않습니다.

| 영역 | 구매 기간 | 기록 확보 조건 | 후보 주문 | 사용 제안 주문 | 사용 제안 아이템 행 |
|---|---|---|---:|---:|---:|
| 학습 | 데이터 시작부터2018-01-01 전 | 배송·선택 리뷰 기록이2018-01-01 전 | 39,634 | 36,854 | 42,057 |
| 검증 | 2018-01-01부터2018-04-01 전 | 배송·선택 리뷰 기록이2018-04-01 전 | 18,565 | 14,621 | 16,679 |
| 테스트 | 2018-04-01부터2018-08-01 전 | 이후 결과를2018-11-01 전 기록으로 관찰 | 23,785 | 23,783 | 27,191 |

학습 후보에서2,780주문, 검증 후보에서3,944주문은 마감 시각 뒤에 배송 또는 선택 리뷰 기록이 있어 보류합니다. 테스트 후보2주문은 리뷰 시각이 구매 시각보다 앞서므로 격리합니다. 원본 파일에서 삭제하지 않고 별도 배정표에 표시했습니다.

학습·검증·테스트의 위험 주문 수는 각각4,466·2,270·2,715개, 위험 비율은 약12.12%·15.53%·11.42%입니다. 기간별 비율 차이는 성능 해석에 영향을 주므로 함께 보고합니다. 월별 분포를 저장했으며 이 비율을 맞추려고 미래 주문을 학습 영역으로 옮기지 않습니다.

## 정답을 언제 알 수 있었는가

현재 데이터에는 실제 시스템 적재 시각이 없습니다. 따라서 `review_answer_timestamp`를 선택 리뷰의 기록 시각 대리값으로, `order_delivered_customer_date`를 배송 완료 기록으로 사용하고 두 시각 중 늦은 쪽을 ‘현재 완료 주문 표본이 준비된 시각’의 보수적인 대리값으로 제안합니다. 이것이 실제 회사 시스템에서 학습 가능해진 시각임을 증명한 것은 아닙니다.

배송 전 리뷰4,245주문을 발견했습니다. 이를 곧바로 잘못된 기록으로 판단하지 않습니다. 배송 중 불만에 대한 리뷰일 수 있고, 이번 모델은 기존 배송 완료 표본을 유지하므로 두 기록이 모두 확보된 후 사용합니다. 반면 구매 전 리뷰2주문은 시간 순서가 명백히 맞지 않아 시간 검증에서 격리하는 안입니다.

원본 리뷰에는 주 모델 표본 중469주문이 복수 기록을 갖습니다. 기존 노트북은 응답 시각으로 정렬하고 주문별 마지막 리뷰를 선택합니다. 학습 마감 뒤의 최신 리뷰를 가진 주문 중 마감 전 리뷰도 있는 경우가1월 경계6주문,4월 경계3주문입니다. 이 수치는 각 경계 이전 전체 구매 주문에서 센 값이며 두 집단이 서로 배타적이라는 뜻은 아닙니다.

첫 실험에서는 기존 최종 라벨을 과거의 다른 라벨로 교체하지 않습니다. 선택된 최종 리뷰가 당시 없으면 보류합니다. 이 방식은 현재 최종 라벨을 고정한 후향적 진단이며 실제 시점별 리뷰 이력을 완전히 복원하지 않습니다. 3점 제외와 배송 완료 표본 자체가 최종 관측 결과에 조건을 건다는 한계도 남습니다. 실제 서비스 시점 재현은 전체 원본 주문·당시 리뷰 선택·카탈로그 변경 이력을 포함한 별도 데이터 설계가 필요합니다.

검증 기간 말의 정답 미확보 주문을 제외하면 늦은 배송·늦은 리뷰의 구성이 달라질 수 있습니다. 따라서 보류 주문 수와 특성을 반드시 보고하며, 정답이 빠르게 확보된 일부 검증 표본으로 고른 임계값이 전체 미래 주문에서 최적이라고 주장하지 않습니다.

## 11월1일이라는 날짜의 의미

현재 파일에서 주 모델 표본의 마지막 리뷰 시각은2018-10-29입니다. 11월1일은 이 저장 기록들을 포함하도록 잡은 평가 정답 관찰 마감 가정입니다. 실제 데이터 추출일·모든 리뷰가 완결된 날짜라는 근거는 없습니다. 현재 파일에 존재하지 않는 나중 리뷰까지 완전히 관찰했다고 주장하지 않습니다. 학습과 검증 마감 뒤의 정보는 테스트 정답 계산에만 사용하고 모델·대체 통계·임계값 선택에는 넣지 않습니다.

## 학습과 평가에서 고정할 것

- 모델: 기존 Track B LightGBM 설정으로1회 학습을 제안합니다. 하이퍼파라미터 탐색·새 피처·클래스 정책 변경은 포함하지 않습니다.
- 전처리: 위 학습 표본에서만 도시별 좌표·상품·거리 대체 통계와 인코딩을 학습합니다. 날짜 열과 리뷰 시각은 분할·감사 용도로만 쓰며 모델 피처에 넣지 않습니다.
- 임계값: 기존 선택 함수를 그대로 사용하되 새 검증 표본에서만 선택합니다. 기존 무작위 분할의 기준을 그대로 가져오는 경우도 비교 참고로 별도 보고할 수 있지만 테스트 성능으로 기준을 선택하지 않습니다.
- 평가: 아이템 행 지표와 주문별 최대 위험 점수 지표를 함께 저장합니다. 평균 집계는 선택용이 아닌 민감도 비교입니다. 임계값의 주 선택은 기존처럼 아이템 검증 기준을 유지하므로 주문 기준 최적 임계값이라고 부르지 않습니다.
- 보고: 정밀도·재현율·AP·혼동행렬·확인 대상 주문 수·위험 비율·월별 결과를 함께 봅니다. 수치가 이전보다 달라도 시간 변화만의 인과 효과로 해석하지 않습니다. 표본 수·기간·구성·임계값이 함께 달라지기 때문입니다.

## 다음 실행의 산출물과 완료 기준

실행을 승인받으면 기존 학습 함수를 수정하지 않고 별도 시간 검증 진입점을 만듭니다. 입력 해시·기간 경계·제외 사유·분할 ID·모델 설정·학습 대체 통계·검증 임계값 선택표·검증/테스트 예측·아이템/주문별 지표를 새 실행 폴더에 저장합니다. 기존 데이터와 성능표·포트폴리오·NICE는 유지합니다.

검증 기준은 주문 교집합0, 시간 경계 준수, 학습/검증의 기록 확보 시각 준수, 원본키·라벨 일치, 학습 영역 외 대체 통계 미사용, 저장 예측에서 지표 재계산 일치입니다. 성능이 올라야 완료되는 실험이 아니라, 정해진 조건을 정확히 지키고 결과와 한계를 설명할 수 있어야 완료됩니다.

## 이번 설계의 근거와 재현

`scripts/audit_temporal_split.py`의 `main`은 고정 데이터와 원본을 읽어 분할 후보·기록 시각 이상·월별 구성을 점검하고 결과를 새 폴더에 저장합니다. 모델 학습이나 기존 데이터 덮어쓰기는 없습니다. `python3 scripts/audit_temporal_split.py`로 재현할 수 있습니다.

산출물은 [설계 요약](../outputs/experiments/temporal-design-20261003-005953/summary.json), [월별 분포](../outputs/experiments/temporal-design-20261003-005953/monthly_profile.csv), [아이템별 배정안](../outputs/experiments/temporal-design-20261003-005953/proposed_assignments.csv)입니다. 입력 파일 해시와 코드 해시는 요약에 포함했습니다.

[Olist 원 배포 페이지](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)는2026-10-03 확인을 시도했으나 도구에서 컬럼 설명 본문이 제공되지 않았습니다. 따라서 응답 시각이 실제 학습 시스템 가용 시각이라는 주장은 확인된 사실로 쓰지 않았습니다. 현재 설계는 로컬 파일의 관측값과 기존 최신 리뷰 선택 코드에 근거한 가정이며, 이를 명시한 제한적 시간 검증을 제안합니다.


## 설계 후 실제 실행 — 2026-10-03

사용자 승인 후 기존 배정안을 그대로 사용해 Track B를1회 학습했습니다. 검증 아이템에서 정한 긍정 기준 약0.56을 고정했고 테스트는 주문 최대 기준 정밀도13.80%·재현율64.24%·AP0.172195, 확인 대상12,639/23,783주문입니다. 아이템 기준 지표와 평균 집계·월별·상품 수별 결과도 별도 저장했습니다. 전체 표본·기간 조건은 변경하지 않았으며 기존 UI에는 적용하지 않았습니다.

복수 아이템 주문 대부분이 표시되고, 마감 미충족으로 보류된 검증 주문은 낮은 리뷰 비율이 더 높았습니다. 이 두 결과를 후속 원인 점검과 평가 설계 개선의 근거로 남겼으며 추가 학습은 하지 않았습니다. 상세 수치·해석·재현 근거는 결정 로그30절, 실행 파일은 `scripts/audit_temporal_model.py`, 산출물은 `outputs/experiments/temporal-validation-20261003-202427/`입니다.
