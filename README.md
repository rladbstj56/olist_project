# Olist CS 리스크 분석 및 부정 리뷰 사전 탐지

Brazilian Olist e-commerce 공개 데이터를 기반으로, 배송 지연이 고객 리뷰에 미치는 영향을 분석하고 부정 리뷰 가능성을 사전에 탐지하는 운영 분석 프로젝트입니다.

이 프로젝트는 단순히 리뷰 점수를 예측하는 것이 아니라, **배송 완료 후 원인을 진단하는 모델**과 **주문 시점에 위험 주문을 선별하는 모델**을 분리해 설계한 것이 핵심입니다. 팀 프로젝트 이후 개인 재검증 과정에서 데이터 단위, 정보 누수 가능성, 사전 예측 가능성을 다시 점검했습니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 주제 | 배송 지연과 고객 리뷰 하락 간 관계 분석, 부정 리뷰 위험 탐지 |
| 데이터 | Olist 주문, 고객, 상품, 판매자, 리뷰, 위치 데이터 |
| 분석 단위 | 주문-아이템 단위 109,294행, 33개 컬럼 |
| 타깃 | `review_score` 1–3점은 CS 리스크(부정 리뷰), 4–5점은 긍정 리뷰 |
| 주요 방법 | 전처리, EDA, 통계검정, 불균형 이진 분류 모델링 |
| 최종 모델 | LightGBM 기반 사후 진단 모델과 사전 예측 모델 |

## 2. 문제 정의

Olist 데이터에서는 배송이 늦어질수록 리뷰 점수가 낮아지는 패턴이 관찰됩니다. 하지만 실무 관점에서는 단순히 “배송이 늦으면 리뷰가 나빠진다”에서 멈추면 부족합니다.

이 프로젝트에서는 다음 질문으로 문제를 구체화했습니다.

1. 배송 지연은 리뷰 점수 하락과 통계적으로 유의하게 연결되는가?
2. 며칠 이상 지연될 때 CS 리스크가 커지는 운영 기준으로 볼 수 있는가?
3. 배송 완료 후에만 알 수 있는 정보와 주문 시점에 이미 알 수 있는 정보를 구분하지 않으면 모델 평가가 왜곡되지 않는가?
4. 리뷰가 작성되기 전에 위험 주문을 먼저 선별할 수 있는가?

## 3. 데이터와 인스턴스 기준

최종 분석 데이터는 주문별 1행이 아니라 **주문-아이템별 1행**입니다.

| 기준 | 값 |
| --- | ---: |
| 최종 행 수 | 109,294 |
| 고유 `order_id` 수 | 95,784 |
| 고유 `(order_id, order_item_id)` 조합 수 | 109,294 |
| 여러 아이템으로 확장된 주문 수 | 9,507 |

이 기준을 사용한 이유는 상품 카테고리, 상품 무게와 크기, 가격, 배송비, 판매자 정보가 아이템 단위로 제공되기 때문입니다. 다만 리뷰 점수는 주문 단위로 붙기 때문에, 모델 평가와 통계검정에서는 같은 주문이 학습 데이터와 평가 데이터에 동시에 들어가지 않도록 `order_id` 기준 분리를 적용했습니다.

## 4. 분석 흐름

최종 재현 기준 노트북은 `notebooks/` 폴더의 3개 파일입니다.

| 순서 | 노트북 | 역할 |
| --- | --- | --- |
| 1 | `notebooks/01_preprocessing.ipynb` | 원본 CSV 로드, 결측·이상치 처리, 테이블 병합, 배송·거리 파생변수 생성 |
| 2 | `notebooks/02_eda.ipynb` | 탐색적 분석, 상관분석, 배송 지연과 리뷰 점수 차이 통계검정 |
| 3 | `notebooks/03_ml_classifier.ipynb` | 부정 리뷰 이진 분류, 사후 진단 모델과 사전 예측 모델 설계·검증 |

## 5. 주요 결과

### 5.1 배송 지연 여부와 리뷰 점수

정상·조기 배송과 지연 배송의 평균 리뷰 점수는 큰 차이를 보였습니다.

| 비교 | 평균 리뷰 점수 |
| --- | ---: |
| 정상·조기 배송 | 4.21 |
| 지연 배송 | 2.53 |
| 평균 차이 | 1.68 |

Mann-Whitney U 검정 결과, 배송 지연 여부에 따른 리뷰 점수 차이는 통계적으로 유의했습니다. 이는 배송 지연이 고객 경험 악화와 강하게 연결될 수 있음을 보여줍니다. 다만 관찰 데이터 기반 결과이므로 인과로 단정하지 않습니다.

### 5.2 3일 초과 지연 기준 검정

지연 주문만 대상으로 `1–3일 지연`과 `4일 이상 지연`을 비교했습니다. 리뷰 점수는 주문 단위인데 분석 데이터는 주문-아이템 단위이므로, 검정 전 `order_id` 기준으로 주문 1건당 1행만 남겼습니다.

| 지연 구간 | 주문 수 | 평균 리뷰 점수 | 중앙값 |
| --- | ---: | ---: | ---: |
| 1–3일 지연 | 2,591 | 3.75 | 4.0 |
| 4일 이상 지연 | 5,008 | 1.93 | 1.0 |

검정 결과:

- 평균 차이: 1.81점
- Mann-Whitney U 검정: `p < .001`
- 효과크기: Rank-biserial correlation `r = 0.590`, 큰 효과

따라서 3일 초과 지연은 CS 리스크가 커지는 운영 관리 기준으로 제시할 수 있습니다.

### 5.3 모델 성능

긍정 리뷰 비율이 높은 불균형 데이터이므로, 단순 정확도보다 부정 리뷰 재현율, 균형 정확도, Macro F1을 함께 봤습니다.

| 모델 | 사용 시점 | 피처 수 | Accuracy | Balanced Accuracy | 부정 리뷰 Recall | Macro F1 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Track A LightGBM | 배송 완료 후 사후 진단 | 33 | 0.652 | 0.651 | 0.648 | 0.603 |
| Track B LightGBM | 주문 시점 사전 예측 | 22 | 0.600 | 0.599 | 0.597 | 0.553 |
| Baseline | 다수 클래스 예측 | 0 | 0.767 | 0.500 | 0.000 | 0.434 |

Baseline은 정확도만 보면 높지만 부정 리뷰를 하나도 탐지하지 못합니다. 반면 사전 예측 모델은 배송 전 정보만으로도 부정 리뷰의 약 60%를 탐지해, 선제 안내나 배송 우선순위 판단에 활용할 가능성을 보였습니다.

## 6. 모델 설계 판단

### Track A: 배송 완료 후 사후 진단 모델

배송 완료 후에만 알 수 있는 실제 배송일, 지연일, 배송 속도 등을 포함합니다. 이 모델은 주문 시점 예측용이 아니라, 리뷰 결과가 나온 뒤 CS·운영팀이 어떤 배송 요인이 불만과 연결됐는지 진단하는 용도입니다.

### Track B: 주문 시점 사전 예측 모델

배송 완료 후 정보는 제외하고, 주문 시점에 이미 알 수 있는 가격, 배송비, 상품 스펙, 예상 배송일, 지역·거리 정보만 사용합니다. 이 모델은 리뷰가 작성되기 전에 위험 주문을 선별하는 목적입니다.

이렇게 두 모델을 분리한 이유는 모델이 실제 운영 시점에 알 수 없는 미래 정보를 사용하면 평가 성능이 과대평가될 수 있기 때문입니다.

## 9. 한계와 주의사항

- 배송 지연과 리뷰 점수의 관계는 통계적으로 유의하지만, 관찰 데이터 기반 분석이므로 인과관계로 단정할 수 없습니다.
- 리뷰 점수는 주문 단위인데 상품·셀러·가격 정보는 아이템 단위입니다. 따라서 상품 단위 원인 해석에는 주의가 필요합니다.
- 리뷰 텍스트, 고객 성향, 판매자 운영 품질 같은 변수가 추가되면 CS 리스크 원인 해석이 더 정교해질 수 있습니다.
- 사전 예측 모델은 배송 완료 후 정보를 제외했기 때문에 사후 진단 모델보다 성능이 낮지만, 실제 운영 시점에 사용할 수 있다는 점에서 의미가 있습니다.

## 10. Archive Policy

`archive/`는 삭제 대상이 아니라 프로젝트 발전 과정을 보존하는 공간입니다.

- `archive/team_work/`: 팀원별 EDA, 전처리, ML 작업 과정
- `archive/legacy_root_notebooks/`: 현재 최종 노트북의 조상 또는 중간본
- `archive/reference_models/`: 최종 모델로 채택하지 않은 참고 모델

최종 재현과 검토는 `notebooks/`, `data/`, `outputs/`, `docs/`를 기준으로 합니다.
